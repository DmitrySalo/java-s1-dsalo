# Python

## Стиль и границы

Пиши современный Python в существующем стиле проекта и используй возможности только поддерживаемой версии интерпретатора. Сохраняй ясные границы между доменной логикой, I/O, HTTP, хранилищами и интеграциями. До изменения изучи аналогичный код, `pyproject.toml` или иной manifest зависимостей и существующие проверки.

- Используй полные type hints для публичных функций, методов и сложных структур данных; не маскируй проблемы типами `Any` без обоснования.
- Предпочитай маленькие функции, `pathlib.Path`, контекстные менеджеры и явные зависимости. Не вводи глобальное изменяемое состояние.
- Не используй bare `except`, не подавляй исключения и не возвращай неявные sentinel-значения вместо ожидаемых ошибок.
- Разделяй синхронный и асинхронный код: не вызывай блокирующий I/O в `async`-пути без явной изоляции; закрывай клиентов, файлы и соединения.
- Не добавляй зависимости, форматтеры, линтеры или фреймворки, если задача решается уже используемыми инструментами.

## Ввод, ошибки и наблюдаемость

Проверяй внешний ввод на границе и преобразуй ошибки инфраструктуры в понятные прикладные ошибки. Не возвращай клиенту traceback, внутренние адреса или детали провайдера.

Не логируй токены, пароли, персональные данные, полный request/response body или конфиденциальные файлы. Логируй безопасные идентификаторы, тип операции и контекст, достаточный для диагностики.

## Проверка

Следуй конфигурации проекта для форматирования, линтинга, type checking и тестов. Сначала выполняй наиболее узкую проверку затронутого сценария, затем полный релевантный набор. Тесты должны быть изолированы, не использовать реальные секреты и внешние production-сервисы.
