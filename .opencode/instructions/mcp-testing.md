# Тестирование MCP-сервера

## Изолированные проверки

- Тестируй регистрацию каждого tool, его имя, описание, JSON Schema и структурированный формат успешного и ошибочного результата.
- Не используй реальную IDE, LLM, сеть, MongoDB, Kafka, Docker, production-данные или пользовательский домашний каталог в unit-тестах.
- Создавай временный project root и фикстуры файлов для тестов документации и поиска. Проверяй пустой запрос, отсутствующий файл, недопустимый path, `..`, абсолютный путь, symbolic link, исключённые директории, превышение лимита и бинарный файл.
- Для DevOps tool проверяй выбор только разрешённой команды, таймаут, ненулевой exit code, обрезку вывода и запрет неизвестного ключа. Не запускай в тестах реальные Gradle или pytest команды, если достаточно fake process boundary.

## Логи и транспорт

- Проверяй, что `TOOL_CALL` и `TOOL_RESULT` фиксируют tool, безопасные параметры и статус, не раскрывая содержимое, секреты и персональные данные.
- Для `stdio` smoke-проверки подтверждай, что прикладные логи не попадают в `stdout` и не нарушают MCP JSON-RPC обмен.

## Приёмка

- После unit-тестов выполни build и тесты модуля `mcp-server`.
- Проверь конфигурацию OpenCode как основной сценарий. Конфигурации IntelliJ IDEA Ultimate и VS Code документируй и проверяй фактически при доступности клиента.
- Подготовь не менее пяти проверочных запросов, из которых не менее трёх вызывают tool, и сохрани trace со ссылками на код и безопасные подтверждения в репозитории.
