# Безопасность Python

## Недоверенный ввод и исполнение

Считай недоверенными HTTP-запросы, CLI-аргументы, переменные окружения, файлы, десериализованные данные, очереди и ответы внешних сервисов. Валидируй тип, размер, формат и допустимые значения на границе.

- Не применяй `eval`, `exec`, `pickle.loads`, небезопасный `yaml.load`, `shell=True` и не конструируй shell-команды строковой конкатенацией.
- Передавай `subprocess` последовательность аргументов, используй allowlist команд и каталогов, выставляй timeout и проверяй return code.
- Предотвращай path traversal: нормализуй путь, проверяй принадлежность разрешённому корню и не доверяй имени файла от клиента.
- Для исходящих URL применяй allowlist, проверку схемы/host, timeout и ограничение размера ответа; не отключай TLS verification.

## Секреты, данные и доступ

Не записывай секреты, ключи, токены, пароли, персональные данные или production-данные в код, fixtures, логи, URL и ответы. Используй утверждённый runtime-механизм секретов и не раскрывай его значения при диагностике.

Авторизацию и проверку владения ресурсом выполняй в серверном коде для каждого действия, а не в UI или по полученному идентификатору. Не ослабляй authentication, authorization, CORS, CSRF, TLS verification, rate limiting или ограничения доступа без явного согласования риска.

## Проверка

Добавляй негативные тесты для невалидного ввода, отсутствующих прав, обхода пути, запрещённого URL или shell-инъекции, если соответствующая граница меняется. Проверяй, что новые логи и ответы не раскрывают чувствительные данные.
