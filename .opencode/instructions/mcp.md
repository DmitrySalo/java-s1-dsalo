# MCP-сервер

## Область и транспорт

Локальный MCP-сервер располагается в отдельном модуле `mcp-server`. По умолчанию используй Java и официальный MCP Java SDK с транспортом `stdio`; не добавляй сервер в production-процесс `my-scents` и не связывай его с LangChain без отдельного задания.

В `stdio`-режиме `stdout` принадлежит MCP JSON-RPC протоколу. Не используй `System.out`, console appender или стороннюю библиотеку, которая пишет прикладные сообщения в `stdout`. Отправляй диагностические записи в `stderr`; они должны содержать имя tool, безопасные параметры и статус `success` или `error`.

## Tools и контракты

- Каждый tool должен иметь стабильное имя в `snake_case`, ясное описание и строгую JSON Schema входа.
- Включай автоматическую валидацию входной схемы SDK и выполняй прикладную валидацию ограничений, которые невозможно описать схемой.
- Возвращай структурированный объект в `structuredContent`; при необходимости добавляй короткое человекочитаемое резюме в `content`.
- Результат ошибки остаётся структурированным: код, безопасное сообщение и контекст без stack trace, абсолютных локальных путей, секретов и полного содержимого файлов.
- Делай tools read-only по умолчанию. Любой side effect требует отдельного явного контракта, минимального allowlist и тестов.

## Подключение клиентов

OpenCode является основным клиентом. Примеры для IntelliJ IDEA Ultimate и VS Code являются альтернативными конфигурациями одного и того же `stdio`-процесса. Для каждого клиента документируй точные шаги включения, executable, аргументы, рабочую директорию и переменные окружения; не коммить локальные пути и секреты.

Фактические демонстрации храни как безопасный текстовый trace и разрешённые скриншоты. В trace фиксируй пользовательский запрос, ожидаемый tool, фактически вызванный tool, статус и ссылку на серверный лог, но не персональные данные, токены или полные конфигурации.
