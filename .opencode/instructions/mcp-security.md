# Безопасность MCP-сервера

## Файловая система

- Принимай project root только из доверенной конфигурации запуска, а не из аргументов tool.
- Перед доступом преобразуй root и целевой путь в canonical/real path и проверяй, что целевой путь остаётся внутри root после разрешения symbolic links.
- Запрещай абсолютные пути, выход через `..`, symbolic links за пределы root и чтение каталогов как файлов.
- По умолчанию исключай `.git`, `.idea`, `.gradle`, `build`, `node_modules`, `.venv`, `.env` и `.env.*`, ключи, credential-файлы, бинарные файлы и крупные файлы.
- Ограничивай размер читаемого файла, число совпадений, длину строк и итоговый объём ответа. Не возвращай содержимое запрещённого файла или причину, раскрывающую его секрет.

## Процессы

- Команда tool выбирается только по enum/фиксированному ключу из статического allowlist: фиксированные executable, аргументы и рабочая директория.
- Используй `ProcessBuilder` со списком аргументов. Не вызывай shell, не собирай команду конкатенацией строк и не передавай пользовательские аргументы, environment overrides, redirection, pipeline или command substitution.
- Устанавливай timeout, ограничивай stdout/stderr дочернего процесса и корректно заверши process при превышении срока.
- Не запускай destructive команды, публикацию, деплой, миграции, Docker, сетевые утилиты или команды, требующие секретов.

## Секреты и наблюдаемость

- Храни локальные значения только в игнорируемом `.env`; в `.env.example` помещай названия переменных и безопасные шаблоны.
- Не логируй токены, ключи, пароли, user input целиком, содержимое файлов, полные команды, абсолютные пути или stack trace.
- Для каждого вызова лога достаточно: имя tool, безопасный идентификатор выбранного действия, число результатов/байтов и `success`/`error`.
- В `stdio`-режиме прикладные логи направляй в `stderr`, никогда в `stdout`.
