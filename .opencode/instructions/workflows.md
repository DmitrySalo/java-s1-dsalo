# Проверяемые сценарии OpenCode

Этот документ дополняет `AGENTS.md`. Используй его при подготовке и проверке типовых задач для модуля `my-scents`.

## Сценарий 1. Добавление REST-поля парфюма

**Пример промпта:**

```text
Строго следуй AGENTS.md. Добавь в карточку парфюма поле страны происхождения.
Поле должно сохраняться в MongoDB и быть доступно по существующим REST endpoint-ам.
Не меняй публичные пути, HTTP-коды, Protobuf-контракты и зависимости.
Добавь проверки и тесты согласно проектным инструкциям.
```

**Ожидаемый формат ответа:** `План` (если нужна декомпозиция), `Изменения`, `Решения и ограничения`, `Проверка`.

**Критерии готовности:**

- Поле последовательно проведено через value object или enum, entity, `Create...Param`/`Update...Param`, Mongo model/converter, отдельные REST DTO/converter и тесты.
- Controller не обращается к `MongoTemplate` и не передаёт HTTP DTO в use case.
- Поведение старых MongoDB documents без поля определено и описано.
- Выполнены unit-, repository- и HTTP-тесты, соответствующие затронутым границам.

## Сценарий 2. Исправление Kafka delete-event

**Пример промпта:**

```text
Строго следуй AGENTS.md. Исправь обработку FRAGRANCE_EVENT_TYPE_DELETED:
в сценарий удаления передавай ID парфюма из payload.id, а event_id оставь
только идентификатором сообщения. Не изменяй Protobuf-схемы, топики,
зависимости и публичные REST/gRPC/Kafka-контракты. Добавь регрессионный тест,
в котором event_id и payload.id различаются. Не используй локальную Kafka и
Thread.sleep. Запроси ревью code-reviewer, выполни проверки и не создавай commit.
```

**Ожидаемый формат ответа:** `Изменения`, `Решения и ограничения`, `Проверка`, включая результат независимого ревью.

**Критерии готовности:**

- Удаляется агрегат с идентификатором `payload.id`, а `event_id` не используется как ID агрегата.
- Тест воспроизводит прежний дефект различающимися ID и не требует внешней Kafka-инфраструктуры.
- Исключения не подавляются, поэтому существующий retry/DLT остаётся применимым.
- Не выполнены несвязанные изменения, включая устранение feedback loop, если оно не входит в задачу.

## Сценарий 3. HTTP-тест ошибки без изменения поведения

**Пример промпта:**

```text
Строго следуй AGENTS.md. Добавь интеграционный HTTP-тест, который проверяет
ответ API при некорректном fragranceId. Production-код и публичный контракт
не меняй, если анализ не докажет необходимость. Используй BaseIntegrationTest
и REST Assured; не подключайся к локальным MongoDB, Kafka или gRPC.
```

**Ожидаемый формат ответа:** `Изменения`, `Решения и ограничения`, `Проверка`; необходимо отдельно сообщить, если production-код не менялся.

**Критерии готовности:**

- Проверяется наблюдаемый HTTP status и безопасное тело ошибки, а не внутренний converter.
- Тест использует существующий `BaseIntegrationTest` и изолированное окружение Testcontainers.
- Тест не зависит от порядка запуска, реальной сети, секретов или `Thread.sleep`.
- Выполнены точные Gradle-команды для нового и полного набора тестов.
