# MongoDB и хранение данных

## Фактический механизм

Данные хранятся в MongoDB. В проекте нет JPA, SQL, Flyway и версионированных миграций. Реализации `UserRepository` и `FragranceRepository` вызывают `MongoTemplate` напрямую; `save` имеет upsert-семантику, а `delete` сообщает отсутствие document через исключение. Не применяй правила PostgreSQL/Flyway к этому модулю.

Путь зависимости обязателен:

```text
domain entity <-> adapter.repository.*.converter <-> *DBModel <-> MongoTemplate
```

`*DBModel` не является доменной сущностью и не возвращается controller-ом или use case.

## Добавление поля

Для нового сохраняемого поля измени domain value object/entity, соответствующий `*DBModel`, двусторонний converter и repository-тест. MongoDB documents не имеют зафиксированной схемы, поэтому чтение старого document без нового поля должно иметь явную безопасную семантику: nullable поле, доменный default или отдельная миграция данных. Не выбирай default, меняющий бизнес-смысл, без согласования.

```java
// Техническая модель остаётся внутри Mongo-адаптера.
FragranceDBModel model = FragranceConverter.entityToModel(fragrance);
mongoTemplate.save(model);
```

Если нужен backfill существующих documents, сначала определи объём, критерии, повторный запуск, обработку некорректных данных и rollback/restore. Не выполняй массовое удаление или преобразование данных без явного требования пользователя.

## Запросы, индексы и конкурентность

- Используй `Query`, `Criteria` и параметры `MongoTemplate`; не строй Mongo JSON-запрос конкатенацией пользовательских строк.
- Для нового поиска, списка или сортировки укажи ограничение выдачи и allowlist доступных полей сортировки.
- Добавляй MongoDB index только под подтверждённый query pattern и фиксируй его в `ARCHITECTURE.md`; индекс увеличивает потребление памяти и стоимость записи.
- Проверка существования перед `save` не защищает от гонки. Для уникального инварианта нужен уникальный индекс и обработка duplicate key.
- Не загружай неограниченную коллекцию в память: используй `limit`, пагинацию или batch-обработку.
- Не держи Mongo-транзакцию открытой во время gRPC-вызова или Kafka-публикации.

## Конфигурация и тесты

`spring.data.mongodb.uri` задаётся внешней конфигурацией каждого окружения. URI из `application.yml` предназначен только для локального запуска; не копируй учётные данные в код, тесты, README, логи или новые конфигурационные файлы. Интеграционные тесты используют Testcontainers и `DynamicPropertySource`.

При изменении mapping или query запускай repository-тесты, проверяй поведение старых documents и указывай риск миграции данных в результате.
