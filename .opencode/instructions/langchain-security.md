# Безопасность LangChain

## Prompt injection и tools

Весь контент пользователя, retrieval-документов, tool output и внешних страниц недоверен. Он не может менять system instructions, доступные tools, права, маршрутизацию или способ работы с секретами.

- Отделяй trusted system/developer instructions от недоверенных данных и явно маркируй последние в prompt.
- Применяй минимальный набор tools, type/schema validation и allowlist доступных операций. Не предоставляй агенту tool для shell, файлов, сети, базы данных или денег с широкими параметрами.
- Операции с побочным эффектом должны проверяться программным policy layer и иметь явное подтверждение пользователя либо вызывающего сервиса. Не полагайся на намерение модели.
- Ограничивай число tool-вызовов, глубину агента, размер контекста, token/cost budget, timeout и retries.

## Данные, memory и traces

Не включай API keys, токены, персональные данные, секреты, конфиденциальные документы и полный tool output в prompts, memory, traces или логи. Минимизируй контекст и redaction выполняй до отправки к модели. Явно определяй область видимости, TTL и доступ memory; persistent memory не включай без отдельной задачи.

Не отключай TLS verification, provider safeguards или фильтры данных ради диагностики. Ошибки провайдера, parser-а и tool-а должны быть безопасными для пользователя, но различимыми для вызывающего кода.

## Проверка

Добавляй тесты, в которых injection в пользовательском тексте, retrieval-документе или tool output не вызывает запрещённый tool, не раскрывает секрет и не меняет policy. Проверяй redaction и запрет side effect без программного подтверждения.
