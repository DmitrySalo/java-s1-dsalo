# Тестирование Python

## Выбор и изоляция тестов

Следуй тестовому runner-у, структуре и маркерам существующего Python-проекта. Сначала добавляй самый узкий тест, воспроизводящий изменённое поведение, затем запускай полный релевантный набор.

| Изменение | Минимальная проверка |
| --- | --- |
| Чистая функция, dataclass, converter, доменная логика | Unit-тест без I/O |
| Async-логика | Изолированный async unit-тест без блокирующих вызовов |
| HTTP handler или client | HTTP-тест со stub/fake transport |
| Файл, subprocess, внешняя интеграция | Temporary directory и fake/stub boundary |
| Исправление дефекта | Регрессионный тест, который воспроизводит прежнее поведение |

Не обращайся к реальным production-сервисам, секретам, времени, сети или файловой системе пользователя. Фиксируй время, randomness и окружение; очищай созданные данные; не используй `sleep` для синхронизации. Мокай внешние границы, а не тестируемую логику.

## Проверка качества

Запускай formatter, linter, type checker и тесты командами, определёнными в проекте. Если проект их не определяет, не выдумывай новый стек: выполни доступный runner или `python -m compileall` для изменённых файлов и укажи ограничение в результате.
