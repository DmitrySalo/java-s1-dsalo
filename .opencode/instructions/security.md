# Безопасность Ароматеки

## Текущее состояние и обязательное правило

`spring-boot-starter-security` подключён, но явные `SecurityFilterChain`, пользователи и правила авторизации отсутствуют. Следовательно, не утверждай, что REST, gRPC или Actuator уже защищены. Любое добавление аутентификации, авторизации, ownership, TLS, CORS или защиты management endpoint-ов является изменением публичной политики: сначала опиши совместимость и план тестирования.

## Данные и логи

`User` содержит email и телефон -- это персональные данные. JSON-логи используют MDC. Разрешено логировать технические ID и типы событий; запрещено логировать email, телефон, request body, Kafka payload/bytes, токены, cookie, пароли, Mongo URI с учётными данными и stack trace в API-ответе.

```java
// Допустимо: диагностируется сущность без персональных данных.
logger.info("Пользователь обновлён с ID {}", user.getId());

// Недопустимо: email и номер телефона попадают в JSON-лог.
logger.info("Пользователь {} с телефоном {} обновлён", user.getEmail(), user.getPhoneNumber());
```

Секреты, URI с учётными данными, JMX credentials и TLS private keys передавай только через внешний безопасный механизм конфигурации. Не копируй локальные значения из `application.yml` в новые файлы, тесты или документацию. При обнаружении секрета не публикуй его в ответе: укажи файл и необходимость ротации.

## Недоверенные входы

Проверяй данные на каждой внешней границе:

- REST: request body, query parameter, header. Используй Bean Validation для структуры и domain value objects для инвариантов.
- gRPC: проверяй required business fields, enum и ограничения до преобразования в domain entity.
- Kafka: считай bytes и decoded Protobuf событие недоверенными. Проверяй известный event type, обязательный payload и допустимые enum до вызова use case.
- MongoDB: строй запросы через `MongoTemplate` / `Criteria`; не конкатенируй пользовательский ввод в JSON query или сортировку.

Не десериализуй произвольные Java-объекты, не выполняй shell-команды с внешним вводом и не добавляй endpoint, который принимает URL, файл или динамическое выражение, без отдельной модели угроз.

## Внешние соединения и эксплуатация

Для production TLS требуется для MongoDB, Kafka и gRPC. Не отключай certificate verification, deadline или retry limits ради временной диагностики. JMX в Dockerfile запускается без authentication и TLS: не делай его доступным за пределами изолированной локальной среды.

Management endpoints доступны на отдельном порту `8086`, base path `/`; экспонированы `health`, `metrics`, `prometheus`, а health details включены. Перед production нужно ограничить сетевой доступ и определить authentication/authorization. Не добавляй в Actuator новые endpoint-ы без такого решения.

## Перед завершением

1. Проверь новые REST/gRPC/Kafka входы на формат, размер, enum и null/absence.
2. Проверь, что доступ к сущности не определяется недоверенным `userId` из body/query, когда появится authentication context.
3. Проверь отсутствие секретов и PII в новых логах, ошибках и фикстурах.
4. Проверь deadline, controlled retry и безопасное преобразование ошибки для новой интеграции.
5. Добавь негативные тесты на валидацию, authorization/ownership после их появления и обработку невалидных событий.
