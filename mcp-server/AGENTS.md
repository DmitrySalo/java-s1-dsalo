# Инструкции для `mcp-server`

Этот модуль предназначен для локального учебного MCP-сервера. Он не является частью Spring Boot-приложения `my-scents`, не предоставляет REST/gRPC/Kafka API и не должен подключаться к MongoDB, Kafka, LLM или внешней сети без отдельного задания.

## Перед началом задачи

1. Соблюдай корневой `AGENTS.md`, затем эти правила. Пользователь может явно указать базовую feature-ветку; в остальных случаях следуй корневому правилу о ветке от актуальной `main`.
2. До изменения изучи MCP SDK, выбранный клиент IDE, конфигурацию запуска, аналогичные tools и тесты. Для MCP-кода загрузи `mcp-server-development`; для файлов, процессов, `.env` или логов -- `mcp-security`; для проверок -- `mcp-testing`.
3. Не добавляй сервер в состав `my-scents` и не меняй его публичные контракты, Gradle build, зависимости или конфигурацию без прямого требования.

## Архитектурные границы

- Используй Java и официальный MCP Java SDK с локальным транспортом `stdio`, если задание не требует другого.
- `stdout` принадлежит MCP JSON-RPC. Серверная диагностика направляется только в `stderr` и не содержит секреты, содержимое файлов, персональные данные, абсолютные пути или stack trace.
- Tool обязан иметь понятное имя, описание, JSON Schema входа, прикладную валидацию и структурированный результат для успеха и ошибки.
- Tool чтения и поиска работает только внутри trusted project root после canonical-path проверки. Исключай секретные, служебные, сгенерированные, бинарные и неограниченно большие файлы.
- Tool запуска проверок использует только статический allowlist команд через `ProcessBuilder`: без shell, пользовательских аргументов, сетевых или destructive команд; с timeout и ограничением вывода.

## Документация и проверка

- Документируй контракт результата tools, настройку `.env.example`, ограничения доступа и 2--5 шагов включения для OpenCode. Примеры IntelliJ IDEA Ultimate и VS Code являются альтернативными конфигурациями того же `stdio`-процесса.
- Подготовь минимум пять проверочных IDE-запросов. Не менее трёх должны вызвать tool; сохраняй безопасный trace и разрешённые скриншоты в модуле.
- Запускай узкие тесты, затем build модуля. До завершения запрашивай независимое ревью `mcp-code-reviewer`.
- Создавай `promts/<kebab-case-name>.md`, последнюю запись `REPORT.md` и добавляй в Git только файлы текущей задачи без commit.
