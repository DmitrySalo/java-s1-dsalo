Точка входа, создание `StdioServerTransportProvider` и регистрация трёх tools находятся в [McpServerApplication.java:L18-L37](src/main/java/ru/my/scents/mcp/McpServerApplication.java#L18-L37). Сервер обменивается JSON-RPC только через `stdio`; `stdout` не используется для прикладной диагностики.

`run_project_check` использует только фиксированный `ProcessBuilder` argument list, исключает из вложенного запуска только smoke-test, при timeout завершает parent process и его обнаруженные descendants, а при ненулевом exit code возвращает структурированную ошибку `CHECK_FAILED`, а не успех: [ProjectCheckTool.java:L43-L80](src/main/java/ru/my/scents/mcp/ProjectCheckTool.java#L43-L80), [ProjectCheckTool.java:L134-L156](src/main/java/ru/my/scents/mcp/ProjectCheckTool.java#L134-L156). Общий лимит объединённого child-process output равен 8 KiB: при его превышении сервер закрывает поток, завершает процесс и обнаруженные descendants, возвращая `OUTPUT_LIMIT_EXCEEDED` без передачи child-process output: [ProjectCheckTool.java:L51-L72](src/main/java/ru/my/scents/mcp/ProjectCheckTool.java#L51-L72), [ProjectCheckTool.java:L98-L115](src/main/java/ru/my/scents/mcp/ProjectCheckTool.java#L98-L115). Ожидание reader имеет ограниченный grace period: [ProjectCheckTool.java:L64-L68](src/main/java/ru/my/scents/mcp/ProjectCheckTool.java#L64-L68). Регрессионные проверки превышения лимита подтверждают остановку parent process и отсутствие child-process output в структурированной ошибке: [ProjectCheckToolTest.java:L60-L87](src/test/java/ru/my/scents/mcp/ProjectCheckToolTest.java#L60-L87). Успешный результат передаёт только безопасные метаданные `output_bytes`/`output_truncated=false`, без дочернего process output. Настраиваемый Python executable и неработающий Windows backend wrapper исключены из allowlist.

`get_local_documentation` и `search_project` строят immutable in-memory snapshot до начала обработки MCP-запросов: [DocumentationTool.java:L26-L105](src/main/java/ru/my/scents/mcp/DocumentationTool.java#L26-L105), [ProjectSearchTool.java:L31-L144](src/main/java/ru/my/scents/mcp/ProjectSearchTool.java#L31-L144). При невозможности построить initial snapshot tools возвращают безопасные structured errors, не завершая stdio-процесс: [DocumentationTool.java:L49-L50](src/main/java/ru/my/scents/mcp/DocumentationTool.java#L49-L50), [ProjectSearchTool.java:L48-L49](src/main/java/ru/my/scents/mcp/ProjectSearchTool.java#L48-L49). Поэтому handler не открывает файловую систему по пути из tool input и подмена файла либо каталога после запуска сервера не влияет на результат. Snapshot ограничен 10 000 строками и 4 MiB, чтобы не удерживать неограниченный объём памяти. Политика исключает `.ssh` и нормализованно сравнивает `private.key`, `private-key`, `apiKey`, `api-key` и `id-rsa`: [ProjectFileAccessPolicy.java:L22-L29](src/main/java/ru/my/scents/mcp/ProjectFileAccessPolicy.java#L22-L29), [ProjectFileAccessPolicy.java:L191-L206](src/main/java/ru/my/scents/mcp/ProjectFileAccessPolicy.java#L191-L206). Регрессионные тесты snapshot, aggregate limit и sensitive-name denylist: [DocumentationToolTest.java:L46-L67](src/test/java/ru/my/scents/mcp/DocumentationToolTest.java#L46-L67), [ProjectSearchToolTest.java:L66-L107](src/test/java/ru/my/scents/mcp/ProjectSearchToolTest.java#L66-L107). Initial scan всё ещё требует неизменяемого trusted root: portable Java NIO на Windows не имеет descriptor-relative API, которое atomically связывает обход и открытие при враждебной подмене родительского symbolic link.

## Контракт результатов tools

Формат `structuredContent` для success/error описан в [README.md:L17-L40](README.md#L17-L40) и реализован в [ToolResult.java:L6-L18](src/main/java/ru/my/scents/mcp/ToolResult.java#L6-L18). Каждый результат включает `status` и `tool`; успешный ответ содержит `data`, ошибка -- безопасные `error.code` и `error.message`. Поисковые results включают только `query_length`, относительный path, line и `truncated`, без query или содержимого файла. В `content` возвращается краткое человекочитаемое summary. Контракт и безопасные логи проверены в [ToolResultAndLoggerTest.java:L12-L45](src/test/java/ru/my/scents/mcp/ToolResultAndLoggerTest.java#L12-L45).

## Запуск и проверка

Для запуска необходим JDK 25 в `JAVA_HOME`; Java 21 не способен загрузить class file version 69. До запуска MCP-клиента выполните `./gradlew.bat installDist`, затем используйте distribution launcher из конфигурации. Локальные переменные не коммитятся: [.env.example:L1-L2](.env.example#L1-L2), [.gitignore:L1-L3](.gitignore#L1-L3).

После устранения рисков выполнены `./gradlew.bat test --tests "ru.my.scents.mcp.ProjectCheckToolTest"`, `./gradlew.bat test --tests "ru.my.scents.mcp.StdioServerSmokeTest"`, `./gradlew.bat test`, `./gradlew.bat build`, `./gradlew.bat installDist` и `opencode mcp list` с JDK 25. Все Gradle-команды завершились `BUILD SUCCESSFUL`; smoke-test подтвердил три зарегистрированных tools, JSON-RPC-only stdout, шесть валидных tool calls, отклонение двенадцати некорректных input payload до вызова реализации с проверенным `structuredContent` contract и `TOOL_CALL`/`TOOL_RESULT` в stderr. Object вместо string отклоняется без `toString()` и следующий валидный вызов подтверждает доступность сервера. OpenCode вернул `my-scents-local connected`, а фактический запрос `Use only my-scents-local_run_project_check to run the MCP server tests.` вызвал `my-scents-local_run_project_check` с `check=mcp_tests` и вернул `Project check completed.` Скриншоты не создавались: текстовые JSON events агента являются воспроизводимым подтверждением и не содержат секретов, абсолютных путей или содержимого исключённых файлов.
