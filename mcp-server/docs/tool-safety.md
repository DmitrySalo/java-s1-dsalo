# Безопасность tools

При запуске сервера поиск по проекту и локальной документации строят неизменяемые in-memory snapshots. Поэтому tool handler не открывает файлы и не обходит каталоги во время MCP-вызова: подмена пути после запуска не изменяет ответ. Чтобы увидеть изменения файлов, перезапустите MCP-сервер. `MCP_PROJECT_ROOT` и `docs` должны быть неизменяемыми во время initial scan: portable Java NIO на Windows не предоставляет descriptor-relative обход, который атомарно исключает подмену родительского каталога symbolic link локальным процессом.

В snapshot попадают только файлы доверенного настроенного корня. Исключаются секретные, сгенерированные, бинарные, symbolic links и слишком большие файлы, а также `.env*`, `.ssh`, key/certificate formats и имена с `credential`, `secret`, `password`, `token`, `id_rsa`, `private_key`, `private-key`, `api_key` или `api-key`. Проверки проекта используют статический allowlist и никогда не принимают команду или аргументы из запроса tool.
