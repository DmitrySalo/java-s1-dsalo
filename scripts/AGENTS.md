# Инструкции для `scripts`

Эти правила уточняют корневой `AGENTS.md` для скриптов автоматизации и вспомогательных Python-программ. При конфликте действуют приоритеты из корневого файла: явные требования пользователя, этот файл, корневой `AGENTS.md`, тематические инструкции и существующий код.

## Перед началом задачи

1. Для изменения существующего скрипта или документации либо новой доработки обнови локальную `main` из удалённого репозитория, создай от неё отдельную лаконичную ветку `feature/<kebab-case-name>` и работай только в ней. При чужих или незавершённых изменениях, блокирующих эту операцию, не меняй ветки и запроси указания пользователя.
2. Прочитай затронутые скрипты, их вызывающие конфигурации, документацию и существующие проверки. Не делай предположений по шаблонам другого проекта.
3. Для Python-кода прочитай `.opencode/instructions/python-style.md`; для LangChain-агента дополнительно прочитай `.opencode/instructions/langchain.md`.
4. Прочитай дополнительные инструкции по области изменения:

| Область | Обязательный файл |
| --- | --- |
| Python, CLI, async, файлы, subprocess | `.opencode/instructions/python-style.md` |
| LangChain agent, tool, prompt, retrieval, memory | `.opencode/instructions/langchain.md` |
| Python REST-клиент или публичный контракт | `.opencode/instructions/python-api-contracts.md` |
| LangChain input, tool, state или structured output | `.opencode/instructions/langchain-api-contracts.md` |
| Python: внешний ввод, секреты, HTTP, файлы, команды shell | `.opencode/instructions/python-security.md` |
| LangChain: prompt injection, tools, memory, traces | `.opencode/instructions/langchain-security.md` |
| Python-тесты | `.opencode/instructions/python-testing.md` |
| LangChain-тесты | `.opencode/instructions/langchain-testing.md` |

Если задача создаёт риск удаления данных, исполнения недоверенной команды, утечки секрета, несовместимого изменения интерфейса или изменения production-конфигурации, сначала опиши риск и безопасный вариант. Не выполняй destructive действие без явного требования пользователя.

## Python и скрипты

- Следуй имеющимся `pyproject.toml`, requirements-файлам или другой конфигурации инструментария; не добавляй зависимости и не меняй версию Python без явной необходимости.
- Применяй type hints на публичных границах, проверяй аргументы CLI и внешний ввод, используй `pathlib.Path` и контекстные менеджеры для файлов и сетевых ресурсов.
- Не используй `shell=True`, `eval`, `exec`, bare `except` и не подавляй ошибки. Передавай команды в `subprocess` как последовательность аргументов и проверяй exit code.
- Не храни и не логируй ключи, токены, пароли, персональные данные, целые request/response body или конфигурацию с учётными данными. Используй переменные окружения или утверждённый механизм секретов.
- Скрипт должен явно завершаться с ненулевым кодом при неустранимой ошибке, быть идемпотентным, когда это возможно, и не обращаться к production-инфраструктуре по умолчанию.

## LangChain

- Валидируй данные до вызова tool и ответ tool после него; отделяй read-only операции от операций с побочным эффектом.
- Не позволяй недоверенному тексту менять системные инструкции, доступные tools, policy или секреты. Ограничивай время, retries, контекст и число tool-вызовов.
- Для тестов используй fake/stub LLM и tools; не используй реальные API keys, сеть, production model или vector store.

## Проверка и документация

Запускай команды форматирования, линтинга, type checking и тестов, заданные в затронутом Python-проекте, начиная с узкой проверки. Если проект их не определяет, выполни хотя бы компиляцию изменённых файлов через `python -m compileall` с используемым интерпретатором и сообщи ограничение. Не запускай скрипт против production-системы для проверки.

Перед завершением запроси независимое ревью: `python-code-reviewer` для Python-кода или `langchain-reviewer` для LangChain-изменения. Добавь изменения в Git без commit. Для каждого задания создай `promts/<kebab-case-name>.md`, затем добавь в конец `REPORT.md` запись с датой, кратким результатом и ссылкой на этот файл согласно корневому `AGENTS.md`.
